El Problema

¿Por qué necesitamos AOP?

La POO es excelente para modelar el dominio, pero falla con los cross-cutting concerns: comportamientos que se repiten en todas las clases.

Con AOP, logging, seguridad y transacciones se definen una sola vez en un Aspecto.

Sin AOP

El problema: código repetido

// Esto se repite en las 50 clases del sistema:
public void procesarPedido(Pedido p) {
    log.info("Inicio procesarPedido");    // logging
    checkAuth(usuario);                    // seguridad
    long t = System.currentTimeMillis();  // timing

    pedidoRepo.save(p);  // ← lógica real

    log.info("Fin: " + (System.currentTimeMillis()-t) + "ms");
}
// → Cambiar el formato del log = tocar 50 clases
Con AOP

La solución: separación de concerns

// Se define UNA vez, aplica en toda la app:
public aspect LoggingAspect {
    pointcut serviceMethods() :
        execution(* com.app.service.*.*(..));

    before() : serviceMethods() {
        System.out.println("Inicio: "
            + thisJoinPoint.getSignature());
    }
    after() : serviceMethods() {
        System.out.println("Fin del método");
    }
}
// El servicio queda completamente limpio

Los 5 conceptos clave

Módulo que encapsula un cross-cutting concern.

Punto en la ejecución donde puede actuar un aspecto.

Aspect

Aspect — el módulo transversal

Equivale a una clase en OOP, pero para comportamiento transversal. Se declara con la palabra reservada aspect y puede ir en un archivo .aj.

Un aspecto es la unidad de modularización en AOP, como las clases son en OOP.
public aspect LogAspect {
    // pointcuts, advices
    // e inter-type declarations
    // van aquí adentro
}
Join Point

Join Point — ¿dónde puede actuar?

Punto bien definido en la ejecución del programa:

Llamada a método

call(* Service.*(..))

Ejecución de método

execution(* Service.*(..))

Constructor

initialization(Clase.new(..))

Acceso a campo

get(int Clase.campo)

Handler de excepción

handler(Exception)

Inicialización estática

staticinitialization(Clase)

Pointcut

Pointcut — ¿cuáles Join Points?

Expresión que selecciona un conjunto de Join Points. Soporta comodines y operadores lógicos.

// Todos los métodos de cualquier clase Service
pointcut serviceMethods() :
    execution(* com.app.service.*.*(..));

// Métodos que reciben exactamente un String
pointcut withString() :
    execution(* *.*(String));

// Combinando: service Y que reciban String
pointcut serviceWithString() :
    serviceMethods() && withString();

// Comodines:
// *  → exactamente un token (paquete, clase, método, parámetro)
// .. → cero o más tokens (paquetes o parámetros)
Weaving

Weaving — tipos de tejido

Compile-time

El compilador ajc teje los aspectos durante la compilación. Mejor rendimiento, sin overhead en runtime.

Load-time

El agente de AspectJ teje cuando la JVM carga las clases. No requiere recompilar.

Runtime

Usado por Spring AOP mediante proxies dinámicos. Más simple pero limitado a métodos públicos de beans.

Sintaxis

Declaración de Aspectos

[ privileged ] aspect Id
  [ extends Type ]
  [ implements TypeList ]
  [ Per Clause ]
{ Body }
Un aspecto puede declararse como cualquier clase de Java, con modificadores que controlan acceso, herencia e instanciación.
privileged

privileged — acceso total

Permite al aspecto acceder a miembros private de clases externas sin getters/setters.

Útil para aspectos de logging que necesitan inspeccionar estado interno sin modificar la API pública de la clase.
privileged aspect AuditAspect {
    before() : execution(* Account.*(..)) {
        Account a =
          (Account) thisJoinPoint.getTarget();
        // Accede a 'balance' aunque sea private
        System.out.println(
          "Balance: " + a.balance);
    }
}
extends / implements

Herencia en Aspectos

// Aspecto abstracto base con pointcut abstracto
public abstract aspect AbstractLogging {
    abstract pointcut loggedMethods();

    before() : loggedMethods() {
        System.out.println("Entering: " + thisJoinPoint.getSignature());
    }
}

// Aspecto concreto que extiende el abstracto
public aspect ServiceLogging extends AbstractLogging {
    pointcut loggedMethods() :
        execution(* com.app.service.*.*(..));
}

Reglas importantes

Un aspecto no se puede instanciar con new.
Una clase no puede extender un aspecto.
Un aspecto no puede extender un aspecto no abstracto.

Beneficio

Permite definir el comportamiento base una vez y reutilizarlo para distintos pointcuts en múltiples aspectos.

Per Clause

Per Clause — instanciación

Por defecto los aspectos son singleton. Las Per Clauses controlan cuántas instancias existen:

issingleton()

Una instancia global. Comportamiento por defecto.

perthis(pc)

Una instancia por objeto en el que actúa el aspecto.

pertarget(pc)

Una instancia por objeto destino del join point.

percflow(pc)

Una instancia por flujo de control que alcanza el pc.

// Una instancia del aspecto por cada objeto Account
public aspect AccountAudit perthis(execution(* Account.*(..))) {
    private int ops = 0;
    after() : execution(* Account.*(..)) { ops++; }
}
Compiladores

Compiladores para AspectJ

ajc

Compilador oficial, parte de las herramientas del proyecto Eclipse. Estándar de producción.


Se integra con Maven/Gradle mediante el aspectj-maven-plugin. Soporta compile-time y load-time weaving.

abc

AspectBench Compiler — diseñado para investigación. Extensible y optimizado.


Permite agregar extensiones al lenguaje de aspectos. Producido en aspectbench.org.

En la práctica: ajc es el compilador para proyectos reales. mvn compile con el plugin lo invoca automáticamente y realiza el weaving.

Los 5 tipos de Advice

El advice define cuándo y cómo actúa el aspecto respecto al Join Point.

around() { inicio...
→
before()
→
método()
→
after()
→
...fin }

before()

Antes del método

after()

Siempre al final (como finally)

after() returning

Solo en éxito

after() throwing

Solo si hay excepción

around()

Envuelve completamente

before / after

before() y after()

public aspect TimingAspect {

    pointcut serviceMethods() :
        execution(* com.app.service.*.*(..));

    // Antes del método — no puede detener la ejecución (salvo excepción)
    before() : serviceMethods() {
        System.out.println("Inicio: " + thisJoinPoint.getSignature());
    }

    // Siempre al final — éxito O excepción (equivale a finally)
    after() : serviceMethods() {
        System.out.println("Fin: " + thisJoinPoint.getSignature());
    }
}
after returning / throwing

after() returning y throwing

public aspect ResultAspect {

    pointcut query() : execution(* Repository.find*(..));

    // Solo si terminó sin excepción — puede acceder al valor de retorno
    after() returning(Object result) : query() {
        System.out.println("Resultado: " + result);
    }

    // Solo si lanzó excepción — puede acceder a la excepción
    after() throwing(Exception ex) : query() {
        System.err.println("Error en consulta: " + ex.getMessage());
    }
}
around

around() — control total

public aspect CacheAspect {

    Object around() : execution(* ProductService.getProduct(String)) {
        String key = (String) thisJoinPoint.getArgs()[0];

        if (cache.containsKey(key)) {
            return cache.get(key);  // NO llama proceed()
        }

        Object result = proceed(); // ejecuta el método real
        cache.put(key, result);    // guarda en caché
        return result;
    }
}
// around() puede:
// ✓ Modificar argumentos antes de proceed()
// ✓ Cambiar o reemplazar el valor de retorno
// ✓ Evitar completamente la ejecución del método
Requiere declarar tipo de retorno. Siempre llamar proceed() a menos que intencionalmente quieras bloquear la ejecución.
thisJoinPoint

Atributos del Join Point

before() : execution(* *.*(..)) {
    // Información dinámica del join point actual
    thisJoinPoint.getSignature();       // firma completa del método
    thisJoinPoint.getArgs();            // argumentos pasados
    thisJoinPoint.getTarget();          // objeto receptor
    thisJoinPoint.getThis();            // objeto del aspecto

    // Parte estática — más eficiente (sin overhead en runtime)
    thisJoinPointStaticPart.getSignature();
    thisJoinPointStaticPart.getSourceLocation();

    // Join point que encierra a este (contexto padre)
    thisEnclosingJoinPointStaticPart.getSignature();
}

Hello World

El aspecto más simple

// Hello.java
public class Hello {
    public static void main(String[] args){
        sayHello();
    }
    public static void sayHello() {
        System.out.print("Hello ");
    }
}
// World.aj
public aspect World {
    pointcut greeting() :
        execution(* Hello.sayHello(..));

    after() returning() : greeting() {
        System.out.println("World");
    }
}
// Output: Hello World
Hello.java no tiene ninguna referencia a AspectJ. El aspecto añade "World" sin modificar la clase original.
Call vs Execution

call vs execution — diferencia clave

call()

Se activa en el lugar desde donde se llama al método (el caller). El join point vive fuera del cuerpo del método.

execution()

Se activa dentro del cuerpo del método (el callee). Si Child hereda de Parent, la ejecución sigue viviendo en Parent.

public aspect Tracer {
    // call: actúa donde se hace la invocación
    before() : call(* Child.*()) { System.out.println("CALL"); }

    // execution: actúa dentro del método heredado de Parent
    after() : execution(* Parent.greet()) { System.out.println("EXEC"); }
}
// person.greet() siendo Child: dispara CALL y EXEC
ITD — Context Passing

Inter-Type Declarations — agregar estado

public aspect Logger {

    // ITD: agrega campo a Point sin tocar Point.java
    int Point.numberOfMoves;

    // ITD: agrega método a Point
    public int Point.howMany() {
        return this.numberOfMoves;
    }

    pointcut counts(Point p) :
        execution(void Point.move(double, double)) && this(p);

    after(Point p) : counts(p) {
        p.numberOfMoves++;
    }
}

// Test puede llamar p.howMany() aunque Point no lo declare
Point p1 = new Point();
p1.move(3, 7);
p1.move(3, 11);
System.out.println(p1.howMany()); // 2

Tutorial 1 — Biblioteca

Sistema de Biblioteca — 3 aspectos

El objetivo: controlar la biblioteca sin modificar Library.java.

1 DebtCheckAspect — before rechaza préstamo si el socio tiene deuda.
2 LoanLimitAspect — around bloquea si el socio ya tiene 3 libros.
3 ActivityLogAspect — after returning registra solo operaciones exitosas.
// LoanLimitAspect.aj
public aspect LoanLimitAspect {
    private static final int MAX = 3;

    pointcut lending(Member m, Book b) :
        execution(void Library.lendBook(Member,Book))
        && args(m, b);

    void around(Member m, Book b) : lending(m, b) {
        if (m.loanCount() >= MAX) {
            System.out.println("Límite alcanzado.");
            return; // bloquea sin lanzar excepción
        }
        proceed(m, b); // ejecuta Library.lendBook
    }
}
Tutorial 2 — Calificaciones

Calificaciones — args() + after returning

// GradeValidationAspect.aj — valida rango 0.0-5.0
public aspect GradeValidationAspect {
    pointcut gradeRecording(Student s, String subject, double grade) :
        execution(void GradeBook.recordGrade(Student, String, double))
        && args(s, subject, grade);

    before(Student s, String subject, double grade)
            : gradeRecording(s, subject, grade) {
        if (grade < 0.0 || grade > 5.0)
            throw new IllegalArgumentException(
                "Nota inválida: " + grade + " para " + s.getName());
    }
}

// AcademicRiskAspect.aj — alerta si promedio < 3.0
public aspect AcademicRiskAspect {
    after(Student s) returning(double avg)
            : execution(double GradeBook.computeAverage(Student, ..)) && args(s,*) {
        if (avg < 3.0)
            System.out.println("[ALERTA] " + s.getName()
                + " en riesgo académico. Promedio: " + avg);
    }
}
Tutorial 3 — Caché

Caché con around()

public aspect CacheAspect {

    private Map<String, Double> cache = new HashMap<>();

    pointcut priceQuery(String id) :
        execution(double ProductCatalog.getPrice(String)) && args(id);

    pointcut priceUpdate(String id) :
        execution(void ProductCatalog.updatePrice(String, double)) && args(id, *);

    // Cache hit → retorna sin tocar la BD
    double around(String id) : priceQuery(id) {
        if (cache.containsKey(id)) {
            System.out.println("[CACHE HIT] " + id);
            return cache.get(id);
        }
        double result = proceed(id); // consulta real
        cache.put(id, result);
        System.out.println("[CACHE SET] " + id + " = " + result);
        return result;
    }

    // Invalida caché cuando el precio cambia
    after(String id) : priceUpdate(id) { cache.remove(id); }
}

¿Cuándo usar AOP?

✓ Úsalo para...

  • Logging y trazabilidad
  • Medición de performance
  • Autenticación y autorización
  • Manejo de transacciones de BD
  • Auditoría y registro de actividad
  • Caché de resultados
  • Validación de parámetros de entrada
  • Retry automático con backoff

✗ No lo uses para...

  • Lógica de negocio principal
  • Proyectos pequeños o scripts
  • Cuando el equipo no conoce AOP
  • Cuando la "magia" dificulta el debug
  • Reemplazar inyección de dependencias
  • Lógica diferente por cada clase
Resumen

Lo que aprendimos

El problema que resuelve AOP

Los cross-cutting concerns se repiten en decenas de clases con OOP puro, violando DRY y SRP. AOP los externaliza a Aspectos.

Los 5 conceptos esenciales

Aspect → módulo. Join Point → dónde puede. Pointcut → dónde quiero. Advice → qué hace. Weaving → cómo se combina.

OOP y AOP: Complementarios

OOP modela el dominio. AOP maneja la infraestructura transversal. Los dos paradigmas trabajan juntos en cualquier aplicación real.

AspectJ en producción

Spring usa AOP internamente para @Transactional, @Cacheable, @Secured. Hibernate usa AOP para lazy loading.
