// El Problema

¿Por qué necesitamos AOP?

La Programación Orientada a Objetos es excelente para modelar el dominio, pero falla cuando hay comportamientos que "cortan" transversalmente todas las clases.

Problema Código repetido en OOP

ServicioA.java / ServicioB.java / ... 
// Cada clase repite el mismo boilerplate:
public void procesarPedido(Pedido p) {
    log.info("Inicio procesarPedido");   // logging
    checkAuth(usuario);                   // seguridad
    long t = System.currentTimeMillis(); // timing

    // lógica de negocio
    pedidoRepo.save(p);

    long ms = System.currentTimeMillis() - t;
    log.info("Fin: " + ms + "ms");       // logging
}
// → 50 clases × este código = pesadilla

Solución Separación con AOP

LoggingAspect.aj 
// Se define UNA vez, aplica en toda la app:
public aspect LoggingAspect {
    pointcut serviceMethods() :
        execution(* com.app.service.*.*(..));

    before() : serviceMethods() {
        System.out.println("Inicio: "
            + thisJoinPoint.getSignature());
    }

    after() : serviceMethods() {
        System.out.println("Fin del método");
    }
}
// → El servicio queda completamente limpio

// Vocabulario

Conceptos Clave

Los 5 pilares que necesitas entender para dominar AspectJ y AOP.

🧩

Aspect

Módulo que encapsula un cross-cutting concern. Equivale a una clase en OOP, pero para comportamiento transversal.

public aspect LogAspect { }
📍

Join Point

Punto específico en la ejecución del programa donde puede actuar un aspecto: llamada a método, constructor, acceso a campo...

method call / execution
🎯

Pointcut

Expresión que selecciona qué Join Points nos interesan. Define dónde se aplicará el advice.

execution(* Service.*(..))
⚡

Advice

El código que se ejecuta en el Join Point seleccionado. Puede ser before, after, around, afterReturning o afterThrowing.

before() : pointcut() { }
🔗

Weaving

Proceso de combinar los aspectos con el código base. Puede ocurrir en tiempo de compilación, carga o ejecución.

compile-time / load-time

// Advice

Tipos de Advice

El advice define cuándo y cómo se ejecuta el código del aspecto en relación al Join Point.

before()

Se ejecuta antes del método. Ideal para validación, logging de entrada, seguridad. No puede detener la ejecución (salvo excepción).

after()

Se ejecuta después siempre, tanto en éxito como en error. Equivalente al bloque finally.

after() returning

Se ejecuta solo en éxito. Puede acceder al valor de retorno. Ideal para auditoría o caché post-ejecución.

after() throwing

Se ejecuta solo si hay excepción. Puede acceder a la excepción lanzada. Ideal para manejo centralizado de errores.

around()

Envuelve el método completamente. Control total: puede modificar args, cambiar el resultado, o evitar la ejecución. Requiere llamar proceed().

around() { inicio...
→
before()
→
método()
→
after()
→
...fin }

Ejemplos Prácticos

11 ejemplos progresivos para dominar AspectJ — desde Hello World hasta sistemas reales con múltiples aspectos.

👋 Hello World AspectJ

El ejemplo más sencillo posible. Una clase Java imprime "Hello " y un aspecto agrega "World" automáticamente sin modificar la clase original.

Clase Java normal — no tiene ninguna referencia a AspectJ. Solo llama a sayHello().
Hello.java
public class Hello {
    public static void main(String[] args) {
        sayHello();
    }

    public static void sayHello() {
        System.out.print("Hello ");
    }
}
El aspecto intercepta la ejecución de sayHello() y añade "World" después de que retorna.
World.aj
public aspect World {
    pointcut greeting() : execution(* Hello.sayHello(..));

    after() returning() : greeting() {
        System.out.println("World");
    }
}
// Output: Hello World

🔧 Ejemplo con Clase Java — TestAsp & Aspect

Demostración de múltiples pointcuts con comodines, manejo de excepciones, constructores, y el advice around() para envolver todos los métodos.

Clase con métodos sobrecargados (metodo1, metodo2, metodo3) y un bloque try-catch para división por cero.
TestAsp.java
public class TestAsp {
    public void metodo1(int numero) {
        System.out.println("Metodo1 con numero: " + numero);
    }
    public void metodo1(int numero, String string) {
        System.out.println("Metodo1 con numero y cadena: "
                + numero + ", " + string);
    }
    public void metodo2(int numero) {
        System.out.println("Metodo2 con numero: " + numero);
    }
    public void metodo3() {
        System.out.println("Metodo3 sin parametros");
    }

    public static void main(String[] args) {
        TestAsp asp = new TestAsp();
        asp.metodo1(1);
        asp.metodo1(1, "HOLA");
        asp.metodo2(1);
        asp.metodo3();

        try {
            System.out.println(1 / 0);
        } catch (Exception e) {
            System.out.println("No se puede dividir en 0");
        }
    }
}
Aspecto con 7 pointcuts distintos: comodines *1, *2, firmas específicas, handler de excepciones, constructor e inicialización.
Aspect.aj
public aspect Aspect {

    static int i = 0;

    // Todos los métodos de TestAsp
    pointcut all() : call(* TestAsp.*(..));
    // Métodos cuyo nombre termina en "1"
    pointcut cut_metodo1() : call(* TestAsp.*1(..));
    // Métodos cuyo nombre termina en "2", solo si i <= 2
    pointcut cut_metodo2() : call(* TestAsp.*2(..)) && if(i <= 2);
    // metodo1 con un entero
    pointcut cut_metodo1_int() : call(* TestAsp.*1(int));
    // metodo1 con entero y String
    pointcut cut_metodo1_IyS() : call(* TestAsp.*1(int, String));
    // Interceptar el handler de Exception
    pointcut exception() : handler(Exception);
    // Interceptar el constructor
    pointcut inita() : initialization(TestAsp.new());

    before() : exception() {
        System.out.println("Alguien dividio por 0!");
    }

    before() : inita() {
        System.out.println("Entrando al constructor "
                + thisJoinPoint.getSignature());
    }

    after() : cut_metodo1() {
        System.out.println("Despues de metodo1, i=" + i);
        i++;
    }

    after() : cut_metodo2() {
        System.out.println("Despues de metodo2, i=" + i);
        i++;
    }

    after() : cut_metodo1_int() {
        System.out.println("Despues de metodo1(int)");
    }

    after() : cut_metodo1_IyS() {
        System.out.println("Despues de metodo1(int,String)");
    }

    void around() : all() {
        System.out.println("----------------");
        proceed();
        System.out.println("----------------");
    }
}

✳️ Comodines "*" en Pointcuts

Los comodines permiten seleccionar múltiples métodos con una sola expresión. * coincide con exactamente un parámetro, .. con cero o más.

Clase con métodos sobrecargados. Observa cómo los pointcuts los seleccionan selectivamente.
AOPDemo.java
public class AOPDemo {
    public static void main(String[] args) {
        AOPDemo demo = new AOPDemo();
        demo.method1(99);
        demo.method1(99, "stringvalue");
        demo.method2("stringvalue");
    }

    public void method1(int number) {
        System.out.println("executing method1(int)");
    }

    public void method1(int number, String value) {
        System.out.println("executing method1(int,String)");
    }

    public void method2(String value) {
        System.out.println("executing method2(String)");
    }
}
Tres pointcuts distintos usando comodines: (*,*) = exactamente dos params, (..) = cualquier número, (*) = exactamente uno.
DemoAspect.aj
public aspect DemoAspect {
    // Coincide: method1(int, String)  → dos parámetros exactos
    pointcut callDemoAspectPointcut() :
            call(void AOPDemo.method1(*, *));

    // Coincide: method1(int), method1(int,String), method2(String)
    pointcut callDemoAspectPointcut2() :
            call(void AOPDemo.*(..));

    // Coincide: method1(int) y method2(String) → un parámetro exacto
    pointcut callDemoAspectPointcut3() :
            call(void AOPDemo.method1(*));

    after() : callDemoAspectPointcut3() {
        System.out.println("Demo Aspect Pointcut - after");
    }

    before() : callDemoAspectPointcut3() {
        System.out.println("Demo Aspect Pointcut - before");
    }
}
// method1(int) dispara before + after
// method1(int,String) NO dispara (requiere exactamente un param)

📞 Call y Execution — Diferencia Práctica

call() intercepta el lugar desde donde se llama al método. execution() intercepta dentro del cuerpo del método. Esto importa mucho con herencia.

La clase padre define greet() y el main. Instancia a Child y llama greet() — el aspecto intercepta en distintos niveles.
Parent.java
public class Parent {

    public void greet() {
        System.out.println("Hello");
    }

    public static void main(String[] args) {
        Child person = new Child();
        person.greet();
    }
}
Child hereda de Parent sin sobrescribir nada. El call intercepta en el caller, execution intercepta en Parent donde vive el cuerpo.
Child.java
public class Child extends Parent {
    // Hereda greet() sin modificarla
}
El aspecto muestra la diferencia: call(* Child.*()) actúa en el sitio de llamada, execution(* Parent.greet()) actúa dentro del método heredado.
ExecTracer.aj
public aspect ExecTracer {

    // call: se activa en el lugar donde se hace la llamada
    before() : call(* Child.*()) {
        System.out.println("CALL a Child.método");
    }

    before() : call(* Parent.*()) {
        System.out.println("CALL a Parent.método");
    }

    // execution: se activa dentro del cuerpo del método
    after() : execution(* Parent.greet()) {
        System.out.println("EXECUTION de Parent.greet() completada");
    }

    after() : execution(* Parent.main(..)) {
        System.out.println("EXECUTION de main() completada");
    }
}
// Nota: person.greet() → activa call(Child.*) y execution(Parent.greet)
// La ejecución vive en Parent aunque la llamada sea a través de Child

⚖️ Calls vs Executions — Demostración con Monitor

call = el acto de llamar a una función (el caller). execution = el proceso de ejecutar el código de la función (el callee). C2 hereda de C1 — observa cómo Monitor solo actúa en la ejecución de C1.

call: se refiere al acto de pasar el control a una función. Si tienes int x = add(1,2), eso es una llamada.
execution: es el proceso de ejecutar las instrucciones dentro de la función. Son el mismo momento lógico pero interceptados desde distintos puntos de vista — el caller vs. el callee.

C1.java
public class C1 {
    public void m() {
        System.out.println("Inside m().");
    }
}
C2.java
public class C2 extends C1 {
    // Hereda m() de C1
}
Usando execution se intercepta cuando el código de C1.m() comienza a ejecutarse, independientemente de si se llamó a través de C1 o C2.
Monitor.aj
public aspect Monitor {
    // execution: actúa cuando el cuerpo de C1.m() se empieza a ejecutar
    before() : execution(* C1.m()) {
        System.out.println("Ejecutando C1.m()");
    }
}
// Si llamas c2.m(), también se dispara porque el cuerpo vive en C1
// Con call(* C1.m()) NO se dispararía para una llamada a c2.m()

📦 Context Passing — Agregar Estado con Aspectos

AspectJ permite que los aspectos agreguen campos y métodos a clases existentes mediante Inter-Type Declarations (ITD). Aquí Logger agrega numberOfMoves y howMany() a Point sin modificarla.

El aspecto declara int Point.numberOfMoves y el método Point.howMany() — se agregan a Point sin tocar su código fuente.
Logger.aj
public aspect Logger {

    // Inter-Type Declaration: agrega campo a Point
    int Point.numberOfMoves;

    // Inter-Type Declaration: agrega método a Point
    public int Point.howMany() {
        System.out.print("Número de movimientos: ");
        return this.numberOfMoves;
    }

    // Captura el objeto Point en el pointcut con this(p)
    pointcut counts(Point p) :
            execution(void Point.move(double, double)) && this(p);

    // Cada vez que Point.move() ejecuta, incrementa el contador
    after(Point p) : counts(p) {
        p.numberOfMoves++;
    }
}
Point no sabe nada de Logger. El aspecto le agrega estado y comportamiento transparentemente.
Point.java
public class Point {
    protected double x, y;

    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }

    public Point() {
        this(0, 0);
    }

    public void move(double x, double y) {
        System.out.println("move: x=" + x + " y=" + y);
        this.x = x;
        this.y = y;
    }

    public String toString() {
        return "x=" + x + " y=" + y;
    }
}
Test puede llamar p1.howMany() aunque Point no declare ese método — lo agrega el aspecto Logger.
Test.java
public class Test {
    public static void main(String[] args) {
        Point p1 = new Point();
        Point p2 = new Point();

        p1.move(3, 7);
        p1.move(3, 11);
        p2.move(10, 10);

        // howMany() es agregado por Logger.aj (ITD)
        System.out.println(p1.howMany()); // 2
        System.out.println(p2.howMany()); // 1
    }
}

🎭 Aspect Behaviours — Implementar Interfaces vía Aspectos

Con declare parents, un aspecto puede hacer que una clase implemente una interfaz y proporcionar los métodos requeridos. Noble obtiene declare() y speak() sin modificar su código.

declare parents hace que Noble implemente Allegiance. Los métodos Noble.declare() y Noble.speak() son proporcionados por el aspecto.
Behavior.aj
public aspect Behavior {

    // Noble implementa Allegiance (sin modificar Noble.java)
    declare parents: Noble implements Allegiance;

    // Proporciona la implementación requerida por la interfaz
    public void Noble.declare() {
        System.out.println("** Noble.declare() via Behavior aspect **");
        System.out.println(this.toString() + " Of House " + this.house);
    }

    // Agrega método adicional a Noble
    public void Noble.speak() {
        System.out.println("** Noble.speak() via Behavior aspect **");
        System.out.println("Good morning, " + this.toString());
    }
}
Allegiance.java
public interface Allegiance {
    public void declare();
}
Noble.java
public class Noble extends Human {

}

// pero Behavior.aj lo hace por ella

🔒 Seguridad — Control de Acceso Centralizado

Un aspecto intercepta el método realizarTransaccion() antes de que ejecute y verifica si el usuario tiene permisos. Si no los tiene, lanza SecurityException sin que el método de negocio sepa nada de esa lógica.

El aspecto captura los parámetros del método con args() y los usa en el advice before para validar acceso.
AspectoSeguridad.aj
public aspect AspectoSeguridad {

    // Captura los 3 parámetros del método en el pointcut
    pointcut realizarTransaccionPointcut(
            String usuario, String operacion, int cantidad) :
        execution(void ServicioTransaccionesSeguro
                .realizarTransaccion(String, String, int))
        && args(usuario, operacion, cantidad);

    // before: se ejecuta ANTES del método de negocio
    before(String usuario, String operacion, int cantidad)
            : realizarTransaccionPointcut(usuario, operacion, cantidad) {
        if (!verificarRoles(usuario, operacion)) {
            System.out.println("Acceso denegado para: " + usuario);
            throw new SecurityException(
                "Usuario no autorizado para: " + operacion);
        }
    }

    private boolean verificarRoles(String usuario, String op) {
        if (usuario.equals("usuario1") && op.equals("depositar")) return true;
        if (usuario.equals("usuario2") && op.equals("retirar")) return true;
        return false;
    }
}
El servicio no tiene ninguna lógica de seguridad — toda está en el aspecto.
ServicioTransaccionesSeguro.java
public class ServicioTransaccionesSeguro {
    public void realizarTransaccion(
            String usuario, String operacion, int cantidad) {
        System.out.println("Usuario: " + usuario
                + " realiza: " + operacion);

        if (usuario.equals("usuario1") && operacion.equals("depositar")) {
            System.out.println("Depósito realizado: " + cantidad);
        } else if (usuario.equals("usuario2") && operacion.equals("retirar")) {
            System.out.println("Retiro realizado: " + cantidad);
        } else {
            System.out.println("Operación no reconocida.");
        }
    }
}
EjemploSeguridad.java
package EjemploSeguridad;

public class EjemploSeguridad {
    public static void main(String[] args) {
        ServicioTransaccionesSeguro servicio =
                new ServicioTransaccionesSeguro();

        // usuario1 puede depositar → OK
        servicio.realizarTransaccion("usuario1", "depositar", 100);
        // usuario2 puede retirar → OK
        servicio.realizarTransaccion("usuario2", "retirar", 50);
        // usuario3 no tiene permisos → SecurityException
        servicio.realizarTransaccion("usuario3", "retirar", 200);
    }
}

⏱️ Tiempo de Ejecución — Performance Monitoring

El aspecto mide el tiempo de ejecución de cualquier método de ProductService automáticamente, sin que la clase de negocio sepa que está siendo cronometrada.

Usa before() para guardar el tiempo de inicio y after() returning para calcular la diferencia solo en caso de éxito.
MethodExecutionTimeLogger.aj
public aspect MethodExecutionTimeLogger {

    private long startTime;

    // Intercepta TODOS los métodos de ProductService
    pointcut methodExecutionTime() :
            execution(* ProductService.*(..));

    before() : methodExecutionTime() {
        startTime = System.currentTimeMillis();
        System.out.println("Iniciando: "
                + thisJoinPoint.getSignature().getName());
    }

    // Solo ejecuta si el método terminó correctamente
    after() returning : methodExecutionTime() {
        long executionTime = System.currentTimeMillis() - startTime;
        System.out.println("Tiempo de ejecución: "
                + executionTime + " ms");
    }
}

🛒 Realización de Pedido — Sistema con 3 Aspectos

Ejemplo complejo: un sistema de pedidos con inventario y tres aspectos que trabajan juntos: verificar stock antes del pedido, registrar actividad en cada operación, y actualizar stock después de realizar el pedido.

before de realizarPedido() — verifica que haya suficiente stock antes de proceder.
VerificarStockAspect.aj
public aspect VerificarStockAspect {

    pointcut realizarPedidoPointcut() :
            execution(void Pedido.realizarPedido());

    before() : realizarPedidoPointcut() {
        Pedido pedido = (Pedido) thisJoinPoint.getTarget();
        for (String producto : pedido.getProductos()) {
            int cantidad = Collections.frequency(
                    pedido.getProductos(), producto);
            if (!InventarioHelper.verificarStock(producto, cantidad)) {
                System.out.println("Stock insuficiente: " + producto);
                throw new RuntimeException(
                        "Stock insuficiente para: " + producto);
            }
        }
        System.out.println("Verificación de stock: OK");
    }
}
before de agregarProducto y eliminarProducto — registra cada operación sobre el pedido.
RegistroActividadAspect.aj
public aspect RegistroActividadAspect {

    pointcut agregarProductoPointcut(String producto) :
        call(void Pedido.agregarProducto(String)) && args(producto);

    pointcut eliminarProductoPointcut(String producto) :
        call(void Pedido.eliminarProducto(String)) && args(producto);

    before(String producto) : agregarProductoPointcut(producto) {
        System.out.println("LOG: agregando '" + producto + "' al pedido");
    }

    before(String producto) : eliminarProductoPointcut(producto) {
        System.out.println("LOG: eliminando '" + producto + "' del pedido");
    }
}
after de realizarPedido() — actualiza el inventario una vez el pedido fue realizado exitosamente.
ActualizacionStockAspect.aj
public aspect ActualizacionStockAspect {

    pointcut realizarPedidoPointcut() :
            execution(void Pedido.realizarPedido());

    after() : realizarPedidoPointcut() {
        Pedido pedido = (Pedido) thisJoinPoint.getTarget();
        for (String producto : pedido.getProductos()) {
            int cantidad = Collections.frequency(
                    pedido.getProductos(), producto);
            InventarioHelper.actualizarStock(producto, cantidad);
        }
        System.out.println("Stock actualizado correctamente");
    }
}
Pedido.java
import java.util.ArrayList;
import java.util.List;

public class Pedido {
    private int id;
    private String cliente;
    private List<String> productos;

    public Pedido(int id, String cliente) {
        this.id = id;
        this.cliente = cliente;
        this.productos = new ArrayList<>();
    }

import java.util.HashMap;
import java.util.Map;

public class Inventario {
    private Map<String, Integer> stock;

    public Inventario() {
        stock = new HashMap<>();
    }

    public void agregarProducto(String producto, int cantidad) {
        stock.put(producto, cantidad);
        System.out.println("Inventario: +" + producto + " x" + cantidad);
    }

    public void eliminarProducto(String producto) {
        stock.remove(producto);
    }

    public boolean verificarStock(String producto, int cantidad) {
        Integer stockActual = stock.get(producto);
        return stockActual != null && stockActual >= cantidad;
    }

    public void actualizarStock(String producto, int cantidad) {
        Integer stockActual = stock.get(producto);
        if (stockActual != null) {
            stock.put(producto, stockActual - cantidad);
            System.out.println("Stock " + producto
                    + ": " + (stockActual - cantidad) + " restantes");
        }
    }
}

🧮 Calculadora con Logs — Trazabilidad de Operaciones

Un aspecto de logging registra en archivo el inicio y fin de cada operación de la calculadora con timestamp preciso, separando completamente la lógica de negocio del registro.

La calculadora es pura lógica de negocio — sin ninguna línea de logging o E/S de archivos.
Calculadora.java
public class Calculadora {
    public double sumar(double n1, double n2) {
        return n1 + n2;
    }

    public double restar(double n1, double n2) {
        return n1 - n2;
    }

    public double multiplicar(double n1, double n2) {
        return n1 * n2;
    }

    public double dividir(double n1, double n2) {
        return n1 / n2;
    }
}
El aspecto intercepta los 4 métodos con pointcuts específicos. Cada before/after escribe una línea en log.txt con timestamp.
LogCal.aj
import java.io.BufferedWriter;
import java.io.File;
import java.io.FileWriter;
import java.io.IOException;
import java.util.Calendar;

public aspect LogCal {
    Calendar cal = Calendar.getInstance();
    File file = new File("log.txt");

    pointcut sumMethod()  : execution(* Calculadora.sumar(..));
    pointcut restMethod() : execution(* Calculadora.restar(..));
    pointcut multMethod() : execution(* Calculadora.multiplicar(..));
    pointcut divMethod()  : execution(* Calculadora.dividir(..));

    before() : sumMethod()  { writeLog("Init method sum"); }
    before() : restMethod() { writeLog("Init method rest"); }
    before() : multMethod() { writeLog("Init method mult"); }
    before() : divMethod()  { writeLog("Init method div"); }

    after() : sumMethod()  { writeLog("End method sum"); }
    after() : restMethod() { writeLog("End method rest"); }
    after() : multMethod() { writeLog("End method mult"); }
    after() : divMethod()  { writeLog("End method div"); }

    private void writeLog(String message) {
        String timestamp = "[" + cal.get(Calendar.DATE) + "-"
                + cal.get(Calendar.MONTH) + "-"
                + cal.get(Calendar.YEAR) + " "
                + cal.get(Calendar.HOUR_OF_DAY) + ":"
                + cal.get(Calendar.MINUTE) + ":"
                + cal.get(Calendar.SECOND) + "]";
        try {
            if (!file.exists()) file.createNewFile();
            BufferedWriter bw = new BufferedWriter(
                    new FileWriter(file, true));
            bw.write(timestamp + "\t" + message);
            bw.newLine();
            bw.close();
        } catch (IOException e) {
            System.out.println("Error al escribir log: " + e.getMessage());
        }
    }
}
Main.java
public class Main {
    public static void main(String[] args) {
        Calculadora calc = new Calculadora();
        System.out.println(calc.sumar(1, 2));       // 3.0
        System.out.println(calc.restar(1, 2));      // -1.0
        System.out.println(calc.multiplicar(1, 2)); // 2.0
        System.out.println(calc.dividir(1, 2));     // 0.5
    }
}

AspectJ vs Spring AOP

Ambos implementan AOP en Java, pero con diferencias importantes. AspectJ es más poderoso; Spring AOP es más sencillo de configurar.

Característica AspectJ (compile-time) Spring AOP
Tipos de Join Points Métodos, constructores, campos, excepciones, inicialización Solo métodos públicos
Clases interceptables Cualquier clase Java Solo beans de Spring
Performance ✓ Mejor (sin overhead en runtime) ~ Pequeño overhead por proxy
Configuración Requiere plugin Maven/Gradle ✓ Automática con Spring Boot
Weaving Compile-time, Load-time Runtime (proxies dinámicos)
Inter-type declarations ✓ Sí (agregar campos/métodos) ✗ No
declare parents ✓ Sí ✗ No
Curva de aprendizaje Mayor ✓ Menor
Casos de uso Máximo control, sin Spring, sistemas legados Apps Spring típicas de producción
En el mundo real: Spring usa AspectJ internamente. @Transactional, @Cacheable, @Secured y @Async son todos aspectos bajo el capó.

¿Cuándo usar AOP?

AOP no es una bala de plata. Úsalo cuando el beneficio de separación supera la complejidad añadida.

✓ Úsalo para...

  • Logging y trazabilidad de métodos
  • Medición de performance / métricas
  • Autenticación y autorización centralizada
  • Manejo de transacciones de base de datos
  • Auditoría y registro de actividad
  • Retry automático con backoff
  • Caché de resultados de métodos
  • Validación de parámetros de entrada

✗ No lo uses para...

  • Lógica de negocio principal del dominio
  • Proyectos pequeños o scripts simples
  • Cuando el equipo no conoce AOP
  • Cuando la "magia" dificulta el debugging
  • Reemplazar inyección de dependencias
  • Lógica que varía por cada clase individualmente
// Resumen Final

Lo que aprendimos

El problema que resuelve AOP

Los cross-cutting concerns (logging, seguridad, transacciones) se repiten en decenas de clases con OOP puro, violando DRY y SRP. AOP externaliza ese código a Aspectos.

Los 5 conceptos esenciales

Aspect → módulo del concern. Join Point → dónde puede actuar. Pointcut → dónde QUIERO que actúe. Advice → qué hace. Weaving → cómo se combina.

OOP y AOP: Complementarios

OOP modela el dominio (clases, herencia, polimorfismo). AOP maneja la infraestructura transversal. Los dos paradigmas trabajan juntos en cualquier aplicación real.

AspectJ en producción

Spring Framework usa AOP internamente para @Transactional, @Cacheable, @Secured. Hibernate usa AOP para lazy loading. Mockito usa proxies AOP.

"AOP no es una bala de plata, pero es una herramienta poderosa en el arsenal del desarrollador. El secreto está en usarla con juicio: cuando el código de negocio empieza a llenarse de lógica de infraestructura repetida, ese es el momento de crear un Aspecto."
